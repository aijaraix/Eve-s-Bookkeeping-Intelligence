# Eve's Bookkeeping — Page-by-Page Public Website Implementation Standard

Status: canonical implementation structure for the final public-site build.

## 1. Source-of-truth precedence

Use this precedence whenever references conflict:

1. Current physical product/runtime truth and verified capabilities.
2. `docs/website-launch/01_CONTENT_TRUTH_AND_CLAIMS_AUDIT.md`.
3. This page-by-page implementation standard.
4. `docs/website-launch/00_WEBSITE_LAUNCH_MASTER.md` and `03_LAUNCH_ACCEPTANCE_AND_BUILD_ORDER.md`.
5. Canonical brand assets/tokens in the website asset package.
6. Owner-supplied screenshots and Canva boards for visual hierarchy/layout/image direction only.

IMPORTANT: the Canva boards are known to be incomplete. Missing Canva content must NEVER be interpreted as permission to remove a required section, capability explanation, legal/truth boundary, responsive behavior, or CTA.

## 12. Responsive implementation

The concept screenshots are NOT responsive specifications.

Required physical breakpoints/acceptance:
- ~360px small phone
- 390x844 phone
- tablet
- desktop

Mobile requirements:
- purpose-built mobile header/menu
- hero content stacks intentionally; do not scale a desktop screenshot down
- product screenshots crop or switch to mobile/simplified representations
- pricing cards stack
- tables become horizontally scrollable or responsive comparison patterns
- CTA bands reflow without text over unreadable imagery
- minimum touch targets and visible focus states

## 13. Product screenshot policy

Do not reuse concept dashboard screenshots as final product truth when real synthetic product screenshots can be generated from the accepted app.

Final marketing screenshots should be captured from a sanitized synthetic/demo workspace and should include, as appropriate:
- financial overview
- documents list
- evidence/provenance drawer
- exception/review state
- report/deliverable library
- source-to-number trace

No Pfizer or real-customer information.

## 14. Acceptance rule

A public page is not complete merely because it visually resembles a Canva board. It is complete only when:
- every required repo-defined section is present;
- unsupported concept claims are removed/replaced;
- assets are responsive and optimized;
- product screenshots are synthetic and truthful;
- CTAs route to real destinations;
- desktop/mobile/browser acceptance passes;
- customer/app/owner product behavior is not regressed.
