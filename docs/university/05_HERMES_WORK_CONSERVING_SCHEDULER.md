# Hermes Work-Conserving Scheduler

Hermes is the heartbeat/orchestrator. Optimize useful safe throughput, not a literal fixed CPU percentage.

Use a configurable learning resource envelope informed by CPU, RAM, disk, provider quotas/rate limits, model concurrency, cost limits, runtime health and queue pressure. An owner target near 85% means safe available learning capacity, not blind CPU saturation.

Future real customer work has priority and Academy work yields/preempts when required.

When capacity exists, eligible University work includes new exams, failed-case reproduction, regression, evidence re-audit, multilingual expansion, tool evaluation, curriculum acquisition, synthetic/adversarial generation, historical failure replay and Minerva holdouts.

Record why usable capacity is idle.

Dashboard must show queue depth, active/idle workers, physical executions, resource utilization, scheduler decisions, blocked reasons and customer-vs-University allocation.
